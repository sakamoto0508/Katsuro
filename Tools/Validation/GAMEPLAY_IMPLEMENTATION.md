# 追加したゲームシステム（2026-09-10）

TitleSceneで開始入力をすると名前・攻撃の加護・防御の加護を選ぶ画面が開く。選択後「この装備で挑む」で戦闘へ進む。シーンへの手動配置は不要。GameSceneを直接再生した場合は既定の名前・装備で開始する。

## 戦闘

- 攻撃命中でゲージ回復。通常の幽霊回避成功でも回復。ジャスト回避は既存の専用ボーナスを使う。同じ敵攻撃の複数コライダーからは重複取得しない。
- 幽霊化はボタンを離す・攻撃する・ゲージが尽きると解除。開始コスト不足時（0を含む）は0.08秒だけ発動し、消費可能な残量を使い切る。途中の回避報酬でこの短時間を延長できない。
- 幽霊化終了後0.35秒の再使用待ち。開始し直して受付時間だけ更新したり、無限に無敵を繰り返したりしない。
- 高HPほど自然回復が多く、自傷時のゲージ消費が少なく、ジャスト回避時間が長い。HP割合に応じて線形補間する。
- 自然回復は幽霊化・HP回復・自傷の継続中は停止。自傷でゲージが増えてしまう状況を避ける。
- ジャスト回避で得る攻撃バフは最大スタックまで加算、8秒持続し、成功するたび残り時間を更新。1回の幽霊化につきジャスト成功は1回。通常回避報酬は別の敵攻撃に対して取得できる。
- 命は初回を含め2つ。1回目の死亡はその場でHP・ゲージ全回復、能力とジャストバフを解除し、2秒無敵。ボスHPは維持。2回目で敗北演出からタイトルへ戻る。

## 痕跡

- このPCのPlayerPrefsに、勝者の名前・装備2枠・クリア秒数を保存。キーは Katsuro.Champion.v1。
- 勝利だけが保存を更新。敗北では前回勝者を維持。同一プレイの結果を二重に書き換えない。
- 次の戦闘開始時に保存済みの勝者を読み込んで相手を確定。初回は既存ボス（HUDでは名もなき守人）。壊れたデータや範囲外の装備IDでは既定ボスに戻る。
- 名前は16文字まで。空欄では「挑戦者」。名前と選択装備は戦闘HUDにも表示。
- ボスはプレイヤー用ゲージを持たないため装備効果を対応する能力に変換。剛力=攻撃1.2倍、吸魂=攻撃1.1倍、窮地=低HPほど攻撃増加、堅守=被ダメージ0.8倍、霊衣=移動速度1.1倍、息吹=最大HP1.2倍。
- 過去の勝利回数で倍率を累積させず、直前勝者の装備だけを反映。外見・モーションのコピー、オンライン共有は含まない。

## 調整

Assets/Mock/Resources/KatsuroRules.assetをInspectorで編集する。残機、復活無敵、短時間幽霊化、再使用待ち、バフ持続、HP補正、6装備と継承時の倍率をまとめて変更できる。装備選択画面の効果説明も設定値を反映する。

既存PlayerStatusの命中回復量・通常回避回復量・ジャスト回避ボーナス、PlayerStateConfigの基本ジャスト回避時間、LowHpBuffTableの攻撃倍率も引き続き使う。残機の管理はGameplayRules.StartingLivesが担当し、旧PlayerStatusのLife値は参照しない。

## 検証

- 新規ファイルを含む全ゲームスクリプトのMSBuildコンパイル成功。
- 実際の追加ソースを独立したUnityプロジェクトへコピーし、30項目の回帰テストが成功。初回／勝利／敗北／壊れた保存、残機の消費、名前、幽霊化の通常・不足・0ゲージ・連打・途中報酬、装備効果、HP補正、自傷消費を検証。
- 再実行: Tools/Validation/Run-GameplayRegression.ps1。テスト側のcompanyName/productNameを確認してから専用保存キーを操作するため、本番の痕跡を上書きしない。
- ログ: Temp/gameplay-build.log と Temp/gameplay-regression.log。
- 実画面のUI・日本語入力・ゲームパッド操作、シーンをまたいだ一連のプレイ、5〜8分の討伐時間、描画性能は未検証。実際のボス戦での調整は引き続き必要。

確認する流れ: TitleScene → 名前と装備選択 → 自傷・回復・通常回避・ジャスト回避 → 1回目死亡で復活 → 2回目でタイトル → 勝利時に保存 → 次の挑戦で勝者名と装備が相手に反映。

# 戦闘演出・スロー復帰・負荷対策メモ
更新日: 2026-09-10

## 今回の実装

### 1. 敵・プレイヤーのダメージリアクション
- CombatFeedback を両者の初期化時に自動追加。
- 実際の被弾で 0.18 秒の暖色フラッシュと上半身の反動を表示。
- Humanoid の Chest、なければ SkinnedMeshRenderer.rootBone に小さい回転を加える。物理ルートは動かさず、攻撃判定や敵AIを中断しない。
- ジャスト回避、幽霊化中のすり抜け、復活無敵中には被弾リアクションを出さない。
- 専用の被弾アニメーションクリップ、硬直、ノックバックではなく手続き的な見た目のリアクション。非スキンモデルにはこの実装だけではフラッシュが付かない。

### 2. 敵へのダメージ数値
- EnemyController の適用前後の HP 差を表示。装備軽減や残り HP の上限を反映。
- 最大 32 個を再利用。超過時は古い表示を上書き。戦闘開始時に準備。
- 0.85 秒かけて上昇・フェード。通常は白、既存 isCritical フラグが渡った場合は大きい金色。
- 新たなクリティカル抽選は追加していない。
- 画面裏の数値は非表示。実時間で消えるためスローの影響を受けない。

### 3. 刀の軌跡
- プレイヤーと敵の武器コライダーに SwordTrail を自動追加。
- EnableHitbox / DisableHitbox に連動して発光する青白い TrailRenderer を出す。
- BoxCollider の長軸から刃先を推定。幅 0.22、寿命 0.14 秒、最小頂点距離 0.06。
- 影は描画しない。無効化時に軌跡を消し、終了時に生成マテリアルを破棄する。
- モデルによる刃先位置・幅の最終調整は実際のゲーム画面で行う。

### 4. 幽霊化シェーダー
- Resources/CombatGlow.shader を追加。HDRP の ForwardOnly パスで半透明の青い輪郭と明滅を描く。
- 幽霊化開始・終了を PlayerGhostState に接続。旧 Ghost 用 CharacterEffect 呼び出しを置換。
- スキンメッシュのマテリアルを事前に用意し、解除・無効化で元に戻す。毎フレームの BakeMesh は行わない。
- 同じシェーダーを被弾フラッシュと刀の軌跡にも使用。
- 透明な輪郭表現なので衣服など重なるメッシュの見え方は実機確認が必要。

### 5. ジャスト回避後にスローが残る問題
- 原因: StatusEffectManager と HitStopManager がそれぞれ Animator.speed を直接書き、片方が他方の遅い速度を「元の速度」として保存する経路があった。
- AnimationSpeedController に書き込みを一本化。基準速度 × 状態異常倍率 × 一時倍率で決定する。
- ヒットストップは実時間の期限で解除。重ねた一時効果は最後の指定で更新する。
- 状態異常とヒットストップの終了順序にかかわらず、終了した効果だけが除かれる。
- 無効化時は状態異常/VFXと速度を片付ける。ヒットストップ用コルーチンと Animator 配列の都度生成を廃止。

### 6. 負荷対策
- PC と Editor の既定品質を High Fidelity → Balanced に変更。既存 Balanced は SSGI 無効。
- GameScene の描画対象 Terrain: GPU インスタンシングを有効、草の距離 80 → 50、木の距離 5000 → 400。
- 地形の密度、近距離の木、戦闘判定は変更なし。
- 戦闘の通常ログを条件付き CombatLog.Trace に変更。KATSURO_COMBAT_LOG 定義がない限り文字列補間も実行しない。警告・エラーは維持。
- 追加演出は数値32個のプール、短い軌跡、事前生成マテリアルで負荷を抑える。
- FPS / CPU / GPU の改善幅は未計測。「重さが解消した」とはまだ断定できない。HDRP の霧・影・SSAO、環境の多数のプレハブ、既存 VFX は引き続き測定対象。

## 検証
- プロジェクト全体の C# を既存 Unity 参照で MSBuild: コンパイルエラー 0。既存のアセンブリ参照競合・未使用フィールド警告あり。
- Run-FeedbackRegression.ps1: 10 項目成功。両解除順序、重複ヒットストップ、時間0、無効化、実際の StatusEffectManager との連携。
- Run-Regression.ps1: 既存 14 項目成功。敵AIの選択・割り当て、武器コライダー・購読解除。
- Run-ShaderValidation.ps1: Unity 6000.2.7f2 / HDRP 17.2 で CombatGlow のパスを同期コンパイル。エラーなし、supported=True。ゲーム画面の目視確認とは別。
- 自動検証は Temp 以下の隔離 Unity プロジェクトで実施。ゲームを操作した通しプレイと見た目の目視確認は未実施。

## Unity での確認手順
1. TitleScene から戦闘へ。最初の攻撃から数値と軌跡が表示されるか確認。
2. 敵・プレイヤーの被弾でフラッシュと反動、無敵時には出ないことを確認。
3. 幽霊化を長押し、攻撃で解除、ゲージ不足、ストック消費、死亡・タイトル遷移の各経路で外見が戻るか確認。
4. ジャスト回避直後に連続攻撃し、敵のスローとヒットストップが重なっても通常速度に戻るか確認。
5. Development Build の Profiler で同じ場所・同じカメラ・解像度を使い、CPU/GPU フレーム時間、GC、描画数を比較。Editor のインポート中は比較しない。
6. Quality を High Fidelity に戻した場合と Balanced を比較し、遠景・草の見え方を調整。

## ダメージ数値が表示されない問題への対応
- DamageNumbers のルートを RectTransform 付きで生成するよう明示。
- 数字用フォントを LiberationSans SDF に固定し、既定日本語フォントの設定に依存しないよう変更。
- 戦闘カメラを PlayerController.Init から受け取る。MainCamera タグがないカメラでも表示できる。
- WorldToScreenPoint の結果を Canvas のローカル座標へ変換。CanvasScaler の拡縮に対応。
- 初回表示時にも位置と透明度を更新。敵の上部（ルートから高さ1.85）に表示する。
- 最大32個の再利用を維持し、長時間のカウンター増加も循環インデックスに変更。
- C#コンパイル成功。隔離Unityで数字「23」のメッシュ生成、タグなしカメラ、画面中央への投影、80回表示後も32個のプールを確認。
- 検証コード: Tools/Validation/DamageNumberRunner.cs。実戦シーンでの目視確認は未実施。元の症状の単一原因は実戦で再現できていない。

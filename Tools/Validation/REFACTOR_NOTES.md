# スクリプト修正・確認記録（2026-09-08）

対象は Assets/Mock/Scripts 配下のゲームコード。シーン、Prefab、画質設定は今回の修正対象外。作業開始前の TitleScene.unity と HitStopManager.cs の変更は保持し、HitStopManager.cs はその内容を土台に追加修正した。

## フェード・画面遷移

- GlobalFader の sceneLoaded による透明化・非表示化と Start の透明化を撤去。暗転をロード中も維持し、新シーン初期化後にフェードインする。
- フェード画像を永続オブジェクト配下に確保。シーン側に割り当てられた画像がロードで消える問題と、再入場時の重複画像を回避。
- シーン遷移の連打防止、存在しないシーンの検証、破棄時の非同期キャンセル、失敗時の画面復帰を追加。時間停止中もフェードは実時間で進行する。
- タイトル、勝利、敗北、LoadSceneManager、GameManager の遷移を GlobalFader に集約。
- タイトル文字の繰り返し Tween と勝敗表示の Tween を終了時に停止。
- 敗北ビネットを透明から開始し、UI とポストエフェクトの時間基準を統一。無音区間で実際に音声を停止し、生成マテリアルを破棄する。

## その他の修正

- GameManager、PlayerDeadManager、FinalBlowManager をシーンの寿命に合わせ、新しいプレイヤーやUIへの参照が再プレイで更新されるようにした。
- 勝敗演出の二重起動防止、シングルトンの破棄時クリア、遅延処理のキャンセルを追加。
- InputBuffer の有効・無効を InputAction に反映。HUD購読を解放し、プレイヤー状態の終了処理をリソース破棄より先に行う。
- ヒットストップの復帰 Coroutine を保存し、追加ヒットで古い予約を中止。管理オブジェクト無効化時は速度を復元。
- 敵の死亡後にAI・攻撃判定が継続しないようにした。破棄後のエフェクト開始をキャンセル。
- 毎フレームの Approach が経路探索の更新間隔を無視していた問題を修正。
- 敵AIの抽選用配列、攻撃バリエーション抽選用List、敵武器のリフレクションを除去。RepeatPenaltyを設定値どおりに使用するため、同じ行動の再選択確率は以前と変わる。
- ダメージ重複判定をCollider単位からIDamageable単位に変更。同じ相手に複数Colliderがあっても、1回の攻撃判定で重複加算しない。
- コンボ受付遅延が経過したら予約入力を処理。アニメーション終了イベントを受け取れない場合の終了判定を修正。
- ロックオンの対象・カメラ欠損時の参照エラーを防止し、毎フレームのカメラコンポーネント検索を削減。
- SEプールの最大数を初期値32に制限。全ソース使用中かつ上限到達時は追加SEを再生しない。破棄済みAudioListenerは必要時に再取得する。

## 検証

- Unity 6000.2.7f2 に対応する既存 Assembly-CSharp.csproj をMSBuildでコンパイル。
- 作業シーンから独立した一時Unityプロジェクトで、実際の修正ソースを使う14項目の回帰確認を実行して成功。
- 回帰確認の対象: AIの候補欠損、反復倍率0/1/0.25、無効な重み、重み付き分布、1000回の意思決定で管理メモリ割り当て0、武器の初期無効化、型付きRelay、重複購読防止、購読解除、攻撃ダメージと解除時リセット。
- 再実行: PowerShellで `Tools/Validation/Run-Regression.ps1`。結果ログは `Temp/refactor-regression.log`。
- これはゲーム全体のPlay Modeテストではない。フェードの実表示、勝敗から再プレイ、ヒットストップとコンボの体感、FPS改善率は未計測。

## Unityでの確認手順

1. TitleSceneから開始し、開始キー・開始ボタンを連打。暗転→ロード中は黒→フェードインとなり、二重ロードや一瞬の表示がないことを確認。
2. 敗北と勝利の両方でタイトルへ戻り、再度ゲーム開始。UI・入力・BGMが動作し、ビネットや古い画面が残らないことを確認。
3. 連続ヒット時にヒットストップが復帰すること、受付遅延付きコンボが1回の追加入力で進むこと、複数Colliderの相手へのダメージが重複しないことを確認。
4. 同じ場面をProfilerで比較。今回の描画設定は変更していないため、HDRP・地形・反射の描画負荷は別途計測が必要。

## 残る確認点

- StatusEffectManagerとHitStopManagerはいずれもAnimator.speedを操作する。スロー効果の開始・終了がヒットストップと同時に発生するケースは、今後速度制御を一元化する前に実動作を確認したい。
- 一部の未使用フィールドと既存の外部DLL参照バージョン警告が残る。Inspector互換性のためSerializedFieldの一括削除や名前変更は行っていない。
